# OpenCode详细攻略，开源版Claude Code，免费模型与神级插件

OpenCode 是近期热度最高的 AI 编程工具。它最大的优势在于开箱即用的免费模型，通过简单配置，还能免费接入 Gemini 2.5 Pro、Claude Opus 4.5 等顶级编程模型。OpenCode 可以看作是一个开源版的 Claude Code，几乎具备了 Claude Code 的所有功能，并且对中国用户友好，不会遇到 Claude Code 里限速、封号等一系列麻烦事。

在 OpenCode 里，有几个可以免费使用的主流模型，非常适合新手上手 AI 编程，你可以随意实践与测试。同时，还可以用它来练习 Agent Skills、MCP、SubAgent 等高级特性。本期视频是一个 OpenCode 的完整教程，主要介绍 OpenCode 的四种形态、对比其他 AI 编程工具的亮点，以及重点介绍 OMY OpenCode 这个超强插件等一系列高级用法。

## 一、OpenCode 的四种形态

OpenCode 有四种形态，分别是：命令行、桌面客户端、插件，以及云端运行环境。

### 1. 命令行版本安装
我们先来看命令行版本。这里我准备用第二种方式，也就是通过 Node.js 来安装。首先来到 Node.js 的首页，根据自己的操作系统下载对应的安装包，将 Node.js 安装好。接下来，复制 NPM 的安装命令，打开一个终端窗口，粘贴命令并回车，这样就安装完成了。

输入命令 `opencode` 就可以直接启动。进入页面后打个招呼，看到返回就说明完全配置成功了，非常简单。

### 2. 桌面客户端安装
接下来看客户端版的安装。在下载页面点击下载客户端，然后一路点击下一步完成安装。打开后，选择一个文件夹作为项目文件夹，就可以直接开始使用了。

需要注意的是，OpenCode 的客户端并不是一个完整的 IDE，它只有基础的对话框功能，而且目前处于 Beta 测试版。我试用下来 Bug 还是比较多的，所以本期视频主要以命令行版本为例进行操作。

### 3. 插件版安装（以 VS Code 为例）
使用插件版 OpenCode 的前提是，需要先把命令行版安装好。这里我以 VS Code 为例。打开 VS Code，在左侧的 Extensions 里搜索 OpenCode，找到对应插件并点击安装。安装好后，按快捷键 `Ctrl+Shift+P` 打开命令面板，输入命令 `Open OpenCode` 并回车。

这样就能以插件的形式打开 OpenCode 了。它可以自动关联左侧窗口打开的代码文件，我们还可以选中一些代码，点击快捷键 `Ctrl+Alt+K`，快速将这些代码粘贴到 OpenCode 的聊天窗口里。以上就是插件的全部功能了。

## 二、开箱即用的免费模型

OpenCode 最棒的一点是内置了一些免费模型。我们进入软件后，输入命令 `/models`，后面带有 `free` 标记的，都是可以免费使用的模型。特别是 GLM-4 和 MiniMax-M1，编程能力都相当不错。零配置，开箱即用，输入需求就可以直接编程，很适合新手用它们来练习 AI 编程。

## 三、神级插件推荐：接入顶级编程模型

接下来，我要推荐一个插件，叫 OpenCode Anti-Gravity Auth。Anti-Gravity 是谷歌推出的一个 AI 编程 IDE，它里面非常高级，很慷慨地提供了 Gemini 2.5 Pro 和 Claude Opus 4.5 这两个顶级的 AI 编程模型。我们可以借助这个插件，把这两个顶级模型免费接入到 OpenCode 里使用。

在它的 GitHub 首页有安装方式，最简单的就是把一段提示词复制下来，然后粘贴到 OpenCode 里执行，AI 就能自动帮我们完成安装。耐心等待一会儿，插件就安装好了。接着，复制登录命令，打开一个新的命令行窗口执行。在模型供应商处选择谷歌和 Anti-Gravity 的登录方式，Project ID 处直接回车，然后登录自己的谷歌账户。将生成的 URL 粘贴进命令行并回车，选择“N”并回车，这样就配置完成了。

重启 OpenCode，输入 `/models`，在模型选择中就可以找到 Gemini 2.5 Pro 和 Claude Opus 4.5 了。打个招呼，若成功收到回复，就代表配置成功了。

## 四、接入 ChatGPT Codex 编程模型

接下来，我们把另一个好用的编程模型——GPT Codex 也接入到 OpenCode 里。就在前几天，OpenAI 跟 OpenCode 官宣进行了合作，我们可以直接在 OpenCode 里使用 ChatGPT Codex 的编程套餐。

首先，需要在 ChatGPT 官网获取一个至少是 Plus 以上级别的套餐。订阅好后，来到 OpenCode，输入命令 `/connect` 并回车，选择 OpenAI 和 GPT Pro。在浏览器里打开生成的链接，选择继续完成登录。然后回到 OpenCode，输入 `/models`，就可以选到 ChatGPT 的几个模型了。

## 五、通过 OpenRouter 接入几乎一切大模型

除了上面这几种接入 AI 的方式，输入 `/connect` 命令可以查找到 75 种 AI 的接入方式，几乎囊括了所有模型供应商。比如我们可以找到 OpenRouter。这里需要我们填写一个 OpenRouter 的 API Key。我们来到 OpenRouter 的官网，点击“Get API Key”创建一个 Key，把它复制并填写到 OpenCode 里。执行后，一个 OpenRouter 就能接入市面上几乎所有类型的大模型，而且国内用户也可以很方便地获取额度。可以说，只要接入了 OpenRouter，就可以使用几乎一切大模型了。

## 六、编程实战测试与亮点分析

我找了一个之前常用的经典测试案例来测试一下。OpenCode 的表现有几个亮点：

首先，在开始之前，它会反向询问我一些问题，比如是只要代码样例，还是一个完整可运行的程序、有哪些功能是必须实现的、想用哪个 Gemini 模型、环境变量如何保存等等。在动手之前，它会把所有需求细节询问清楚，这点非常不错。

接着，它列出了一个详细的开发计划，并分步骤完成，每完成一步都会标记出来。

第二个亮点是命令行版的代码比对界面，我觉得它是所有命令行类编程工具中做得最好的。整个编程过程没有出现错误，也没有需要代码返工的场景，一次性就完成了开发。这里我使用的编程模型是 GPT Codex，我是通过登录我的 ChatGPT Plus 订阅账号接入的。我觉得它在 OpenCode 里的表现，跟使用原生的 Codex CLI 几乎一致。OpenCode 在底层对各种编程模型都进行了很多工程上的优化，体验相当不错。

## 七、Session 并行开发与历史记录管理

OpenCode 里重点突出了一个叫做 Session 的概念。我们每次与 AI 开启的新对话，就是一个全新的 Session。Session 可以后台运行，而且可以多个并行运行。

例如，刚才生成了一个“你画我猜”的游戏网站，我想增加两个功能：让画笔可以调整颜色，以及增加一个计时器，超过 20 秒游戏就失败。我们先输入第一个需求，增加计时器。在执行过程中，输入 `New` 命令创建一个新的 Session，开始处理第二个需求——调节颜色。输入命令 `/sessions` 就可以看到触发的 Session，前面有旋转符号的，表示它正在后台运行。这样，我们就创建了两个 Session，让两个需求并行开发，还可以在它们之间互相切换，查看执行状态。任务完成后，我们成功利用 Session 功能，并行完成了两个需求的开发。

输入 `/share` 命令，可以把 Session 的对话记录分享成一个网页，地址会自动复制到剪贴板。将地址粘贴到浏览器，就可以看到整个对话记录，包括 AI 如何进行文件修改。有了这个历史记录，我们可以很方便地把编程过程分享给其他用户。输入命令 `/unshare` 可以取消分享，之前的链接就会失效。输入 `/export` 命令，则可以将对话记录导出为一个文件。

## 八、Timeline 检查点：自由回退代码

OpenCode 还有一个亮点功能，就是它的时间线，或者说检查点。输入命令 `/timeline` 并回车，可以看到当前 Session 的所有对话记录。我们可以选择任意一次记录，使用 `Revert` 功能，将代码和聊天内容一起回退到那次对话之前的状态。这样，我们就可以回到任意时间点重新进行修改。

## 九、Agent Skills 的快速迁移

在上期视频中，我们介绍了 Agent Skills 的基础概念及其目录结构。我们可以把 Skill 理解成带目录的说明书，每个文件夹都对应一个 Skill，也就是一个技能包。将一个 Claude Code 中的 Skill 迁移到 OpenCode 里非常简单，只需把目录里的 `.claude` 替换成 `.opencode` 就可以了。

具体操作上，来到 OpenCode 的项目文件夹，新建一个叫 `.opencode` 的文件夹，进去后再新建一个 `skills` 文件夹，然后就可以把之前创建好的技能文件夹直接复制进来。这样，项目就拥有了那些技能。启动 OpenCode 后，提问“你有哪些 Skills？”，它会给出完整回答。当有需要的时候，它就会调用这些 Skills 进行工作。

## 十、MCP 的两种配置方式

接下来看 MCP 的配置方法。OpenCode 里支持两种 MCP：一种是本地方式，通过本地命令执行；另一种是远程方式，即远程调用。

我们先以 `shadcn` 为例配置本地 MCP。来到 OpenCode 的配置文件夹，找到 `opencode.json` 配置文件。从文档站复制 MCP 的配置段，填写名字、类型（local）、命令（command）等信息，并设置 `enabled` 为 true，这样一个本地 MCP 就配置完成了。

再看远程调用的案例，我们以 `context7-mcp-server` 为例。同样地，在配置文件中粘贴远程调用的配置段，类型为 `remote`，填写好 URL 和 headers 中的 API Key 等信息，重启后即可生效。输入 `/mcp` 命令，就可以看到我们刚才配置的两个 MCP。

## 十一、OMY OpenCode 超强插件详解

OMY OpenCode 是 OpenCode 上一个最火的编程插件，它本质上是一系列工具、MCP 和编程 Agent 的组合捆绑包。

在工具方面，它集成了：LSP 高级版（借助编程语言的语法和语义，帮助 AI 快速理解和定位代码）、AST 工具（通过代码的语法树进行关联搜索）、Locate 工具（借助多模态大模型的视觉能力，理解图片和 PDF 等信息），以及 Delegate Task、Background Task 这些 Agent 任务分配和后台调度工具。

插件还内置了三个 MCP Server：Web Search（用于网络搜索）、Context7（用于获取最新的文档）、Grep App（用于在 GitHub 仓库快速搜索代码）。此外，插件还内置了七大编程智能体，分别是：西西弗斯（主智能体，用来规划和调度任务）、先知（负责架构设计、代码评审）、图书管理员（查阅文献）、探索者（网络搜索）、前端工程师、文档编写者和多模态专家。插件为每个智能体都分配了一个最适合它工作的大模型，比如前端工程师使用前端能力最强的 Gemini 2.5 Pro，主 Agent 使用的是 Claude Opus 4.5。据说，这是作者花了 24000 美元的 Token 找到的最适合的 AI 编程团队。

### 1. 安装与配置
在它的 GitHub 首页有一段安装提示词，完整复制下来，粘贴到 OpenCode 里并执行。安装时，插件会询问订阅情况，根据自己的实际拥有情况（如是否有 GPT Plus、Gemini 订阅）选择即可。
安装完成后，可以在配置文件夹里找到 OMY OpenCode 的配置，可根据需要调整七大智能体所使用的模型。

### 2. UltraWork 并行调度模式
这个插件主要有几种用法。首先，可以敲 `@` 然后挑选一个智能体为我们工作。还有一个重要用法，就是输入魔法词 `ULW`，即 UltraWork。输入后，OMY OpenCode 会尽可能调用它的一切潜能，把任务分配给多个智能体，并让主智能体西西弗斯进行居中调度，并行运行。它会先拆分任务清单，同时开启多个后台任务疯狂调度，完成后可以查看效果，即使是纯文本需求的网页，也能尽量用 Emoji 等实现不错的效果。

### 3. Ralph Loop 长时间循环
OMY OpenCode 还有一个重要玩法，输入命令 `/ralphloop`，即拉尔夫循环。这个模式可以强制 AI 长时间循环，对一个非常难的任务进行持续工作，比如要求它使用某个最新标准重构整个项目，并直到所有测试用例都通过。它可以循环连续运行好几个小时，直到最终任务完成。

## 十二、云端运行环境实战：GitHub 协作

最后来看云端运行环境。这里以 GitHub 为例，它的主要功能是，当我们在 GitHub Issue 或 Pull Request 里输入 `/opencode` 命令，OpenCode 就可以在 GitHub 云端进行工作，比如解释问题、自动修复 Bug 并创建 PR 等。

我们来试一下安装方式。首先将项目上传到 GitHub 仓库。然后复制安装命令执行，选择一个模型提供商和模型（需要用 API Key）。接着，需要将项目里的配置文件提交，并根据指引在仓库的 Actions Secrets 里配置好对应的密钥。

配置好后，比如有用户在 Issue 里提了一个 Bug，我们就可以直接在 Issue 里调用 `/opencode` 命令，让 OpenCode 修复。提交评论后，在项目的 Actions 里可以看到一个正在执行的工作流，这就是 OpenCode 在云端运行。任务完成后，在 Pull Request 里会看到一个代码合并请求，里面包含了修改内容。我们只需点击 Merge 按钮，就能将这次修改合并进代码仓库，对应的 Issue 也成功关闭了。

## 十三、其他重要功能速览

接下来快速过一下 OpenCode 的其他几个重要功能，它们在之前的 Claude Code 和 Codex 视频里也介绍过。

### 1. `/init` 命令
这个命令可以让 AI 通读整个项目文件夹，然后把它学到的关于整个项目的知识，生成一个 `agents.md` 文件。这个文件将作为整个项目的系统提示词，帮助 AI 快速了解项目。

### 2. `/compact` 命令
用来压缩之前对话的上下文，把历史对话提炼成一个简洁的摘要，以释放模型的上下文窗口。

### 3. 自定义命令
除了内置命令，也可以创建自己的命令。在 OpenCode 的配置文件夹中新建一个 `commands` 文件夹，在里面以 Markdown 文件的形式定义自定义命令。可以指定它作用的模式，并写清楚其用途。配置完成后，在 OpenCode 里输入 `/命令名字` 即可运行。

### 4. 自定义智能体
OpenCode 预设了 `plan` 和 `build` 两种智能体，我们也可以创建新的。在配置文件夹中新建 `agents` 文件夹，然后创建 Markdown 文件来定义新的智能体。需要填写它的类型（`primary` 主智能体或 `subagent`），以及描述和行为。定义为 `primary` 的主智能体，可以按 Tab 键直接显式切换；而 `subagent` 则只能在后台，由 AI 自动调度执行。这样，当需要执行相应任务时，它就会被自动调用起来。
